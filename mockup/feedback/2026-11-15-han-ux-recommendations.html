2. Core interaction model

Read document→Select text→Ask or annotate→Explore AI answer→Follow up

The original document remains stable. Questions and answers live in an optional contextual side panel, while highlights and small discussion markers keep them anchored to the relevant passage. Every AI response is itself selectable and annotatable, creating a threaded annotation graph rather than a flat chat history.

4. Interaction details

A. Selection toolbar

Show Ask AI and Annotate as distinct actions. Ask AI opens a composer with the selected text attached; Annotate saves a personal observation without calling the model. Offer quick prompts such as “Explain this,” “Show an example,” and “Find the implementation” inside the question composer, not in the toolbar.

B. Recursive response annotation

AI answers should support the same selection interactions as the document. A follow-up should store its parent response and selected span, preserving context. Use branching threads rather than forcing all follow-ups into a single flat conversation.

C. Provenance and trust

Keep source evidence visually separate from user discussions. Distinguish claims verified in source, asserted by tests, documented, inferred, and not found. AI responses should cite relevant source lines where available and clearly label general explanations or inferences.

D. Discussion discovery

Add small discussion indicators beside annotated passages, counts beside sections, and a navigator grouped by document section. Users should be able to jump from a saved discussion back to its source.

E. Save useful learning

Allow users to save an AI explanation as a note or propose it as a document addition. Do not silently alter the generated codebase map; keep personal notes and AI-generated content in a clearly labeled layer.

5. Implementation priorities

P0
Core annotation loop

Text selection, floating toolbar, contextual question composer, AI response, and recursive response annotations. Make this interaction polished before adding complexity.

P1
Navigation, persistence, and grounding

Discussion markers, saved notes, stable anchors, source previews, provenance badges, and thread navigation.

P2
Advanced exploration

Branching discussion graph, cross-module links, promoting answers into notes, and conversation summarization.

6. Suggested data model

DocumentAnchor: document ID, revision, text quote, start/end offsets, and surrounding-context hash.

Annotation: annotation ID, anchor, kind (note or question), author, timestamp, and content.

Response: response ID, parent annotation/question, answer text, evidence references, and generation metadata.

FollowUp: parent response ID, selected response-text offsets, question text, and resulting response ID.

When a repository map regenerates, attempt quote/context re-anchoring and visibly flag unresolved anchors instead of silently attaching them to the wrong text.

Design decision: Prefer a contextual side panel over inline expanding answers. It keeps the original map readable, gives discussions room to grow, and supports recursive annotations without turning the document into a deeply nested chat.

Mockup is standalone and intentionally uses static demonstration answers. It stores notes only in memory for this page session; no data is transmitted.
